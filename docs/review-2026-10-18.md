## P1 findings

### GDAL vector drivers fetch URLs that untrusted data names

Locations: `src/core/gdal_support.cpp:40-60` and `:101-113`, `src/plugins/gdal_vector.cpp:382-405`.

`initializeGdal` removes whole drivers through `GDAL_SKIP`. The allowed GML and GeoJSON drivers still call `CPLHTTPFetch` for URLs in the document. A probe with the SWAK configuration and driver list showed two requests. A GML `xsi:schemaLocation` with a WFS `DescribeFeatureType` URL caused a plain HTTP GET to that URL. A GeoJSON `crs` of type `link` caused a GET to the linked URL. Any data feed or opened file can therefore make SWAK send requests to internal hosts or to a tracking server. `docs/security.md` says that SWAK removes drivers that fetch any URL.

Install a `CPLHTTPPushFetchCallback` that refuses every fetch while vector data is decoded. Also set `GML_DOWNLOAD_WFS_SCHEMA=NO`. Add tests with a local listener for both payloads.

### Chat text with emoji is sent empty and shows as Sent

Locations: `src/core/chat.cpp:394`, `src/core/chat.cpp:176-180`, `src/core/cot_detail.cpp:24-50`.

`Chat::send` accepts valid surrogate pairs. `writeElement` writes element text only when `safeValue` accepts it, and `safeValue` rejects every surrogate. The text is dropped, and the `valid` flag is not set for text. `writeDetail` never reads that flag. A probe encoded "hello 😀" as an empty `remarks` element. Receivers drop a chat event without text. The sender sees the message change from Queued to Sent.

Use one character rule for all CoT text. Let `safeValue` accept valid surrogate pairs, and make `writeDetail` fail when any value is rejected. See also "One text filter" under repeated code.

## P2 findings: security

### A server can take over and then delete an object from another origin

Locations: `src/core/store.cpp:101-121`, `:205-230`, `src/core/servers.cpp:994`.

`Store::accept` finds an existing row by UID only, and it replaces the row with the new event and its origin. A server can send the UID of a local object, or of an object from another server, with a newer time. The row then gets that server's origin. A later `t-x-d-d` from the same server passes the origin check in `deleteRequest`. `docs/security.md` says that one server cannot delete objects from another server or local objects.

Do not let an update change the origin of an existing row. TAK servers often relay the same UID, so do not simply reject updates from a second server. Keep the first origin for the delete check, or store the set of origins that sent the UID. Add a test where server A replaces a local UID and then sends `t-x-d-d`.

### Protocol-response frames cause deep recursion and large copies

Locations: `src/core/servers.cpp:1094-1112`, `src/core/cot_stream.cpp:151-156`.

`consume` stops the XML reader after each frame that contains `t-x-takp-r`. `CotStream::feed` then copies the rest of the input. When the session stays in XML mode, `consume` calls itself with that copy. One 64 KiB read of short repeated response frames recursed 2848 levels in a probe and kept about 93 MB of copies alive. LAN peers, plain TCP servers, and TLS servers reach this path. LAN peers have no authentication.

Replace the recursion with a loop over an offset. Apply the stop test only to sessions that sent a protocol request.

### The XML DTD check reads only the first 4096 bytes

Locations: `src/core/gdal_support.cpp:221-226`, callers in `src/plugins/gdal_vector.cpp:480`, `:527`, `:557`.

`declaresXmlDocumentType` searches `bytes.left(4096)`. A comment of 5000 bytes before `<!DOCTYPE` hid an internal entity from the check in a probe. The GeoRSS driver then expanded the entity into a feature title. A UTF-16 document also passes the byte search.

Scan the whole prolog up to the root start tag, with a byte limit, and reject documents that are not UTF-8.

### The GDAL raster cache mixes checked and unchecked TLS tiles

Locations: `src/plugins/gdal_raster.cpp:92-103`, `:153-161`.

The cache key hashes the `Service` and `DataWindow` text. The `UnsafeSSL` element is added after the hash. Two sources with the same URL and layer, one with `ignoreTls`, therefore share one cache folder. Tiles fetched without certificate checks are then used for the checked source for 7 days. The MVT path keeps separate `verified` and `unchecked` folders, and `docs/security.md` promises that separation.

Include the certificate policy in the cache key, or use the same two folders as the MVT path.

### Remote text goes into tooltips as rich text

Locations: `src/plugins/chat.cpp:194`, `:258`; `src/plugins/sharing.cpp:59`; `src/plugins/missions.cpp:380`, `:457`; `src/plugins/checklists.cpp:215`, `:235`; `src/plugins/reports.cpp:184`; `src/plugins/files.cpp:48`; `src/core/contacts.cpp:89`; `src/core/server_browser.cpp:355`, `:359`, `:493-495`, `:563`.

These sites show server or peer text in tooltips or in a label with the default `Qt::AutoText`. Qt shows such text as rich text when `Qt::mightBeRichText` matches. A probe returned true for `<b>x</b>` and for an `img` element. `docs/coding-style.md` requires plain remote text. `plainToolTip` in `src/core/provider_table.h` already exists.

Wrap every remote tooltip in `plainToolTip`. Set `Qt::PlainText` on the skipped-layer label.

### Server timestamps convert large numbers to integers

Location: `src/core/missions.cpp:37-44`, used by `readMissions` and `readMissionLogs`.

`static_cast<qint64>(value.toDouble())` runs on any JSON number. A value of `1e300` is undefined behavior. A UBSan probe reported the overflow. `src/core/file_shares.cpp:109-110` already checks a similar cast.

Reject values that are not finite or are outside a valid millisecond range before the cast.

## P2 findings: reliability

### The binary stream timeout measures the wrong time

Location: `src/core/servers.cpp:1136-1147`.

`consumeBinary` keeps `s.partial` until the protocol buffer is empty. It does not reset the time when complete payloads arrive. A server that streams without pause, so that each read ends inside a frame, keeps the first time. `maintain` then closes a healthy session with "Incomplete message timed out." The XML path resets the time after complete frames.

Reset `s.partial` when `feed` returns payloads, then start it again if a frame is still pending.

### A batch with deletes refreshes the wrong rows

Locations: `src/core/store.cpp:115-117`, `:150-152`, `:231-257`.

During a batch, an update records only the first and last changed row numbers. A delete in the same batch removes rows and renumbers the rest. The final `dataChanged` then names moved rows, or rows past the end. Server batches contain deletes.

Emit the pending `dataChanged` before a removal in a batch, or keep changed UIDs and map them to rows at the end.

### One bad receipt blocks all outgoing chat

Locations: `src/core/chat.cpp:42-46`, `:201`, `:483-489`.

`identifier` accepts a message ID with a surrogate pair. `chatReceiptEvent` uses that ID as the event UID, and `eventError` rejects it, so `Servers::send` fails. `flush` stops at the first failure and keeps the receipt. All later receipts and own messages wait. The queue retries every 5 seconds until 256 newer receipts push the bad one out. One direct message from a peer causes this.

Drop an event that fails encoding. Retry only for "not connected" and "queue full". Use the `eventError` rules in `identifier`.

### A stale checklist load changes the wrong checklist

Locations: `src/plugins/checklists.cpp:111-128`, `:245-255`.

Each selection loads a checklist. The `loaded` handler sets `current_` without a check that the reply is for the selected checklist. On error, it keeps the old `current_`. When the user selects A and then B, and B fails or A arrives last, the list shows B but Complete and Pending change a task in A on the server.

Keep the requested UID and server, ignore other replies, and clear `current_` and the table on error.

### An emoji callsign erases all sharing preferences at the next start

Locations: `src/core/object_sharing.cpp:14-20`, `:36`, `:127-129`, `:175-190`; `src/core/contacts.cpp:19-28`, `:40-44`.

`readTakContacts` keeps surrogate pairs. `ObjectSharing::share` stores a recipient with such a callsign, and `savePreferences` writes it. At the next start, `readRecipients` rejects it. `restorePreferences` then ignores the whole document, and the next save writes the empty state over it.

Check recipients in `share` with the `readRecipients` rules. On restore, drop single bad entries, not the whole document.

### CI-TRAP reports fail with spaces or emoji in the title

Locations: `src/plugins/reports.cpp:272`, `src/core/citrap.cpp:268`, `:287-288`, `src/core/data_package.cpp:226-228`.

`Citrap::create` checks `plain(title)` but passes the raw title to `writeDataPackage`. That function fails when `plain(name) != name`. "Fire " and "Fire 🔥" fail with "The package has an invalid name, UID, or entry count."

Set `report.title = plain(report.title, 128)` before the check.

### Remote video events fill the video list for the session

Location: `src/core/video_sources.cpp:202-236`.

Each accepted event with a `__video` element adds a source, also from UDP and LAN peers without authentication. Nothing removes these sources. After 64 URLs, `add` refuses all new sources, also the user's own. An event with the same key also replaces the URL, and its credentials, of a source that the user entered.

Keep manual sources in their own quota. Remove the oldest event sources first. Do not let events change manual sources.

### Data feed painting reads preferences for each shape

Locations: `src/core/data.cpp:507-547`, `:585-620`.

`DataSources::paint` reads `pointSize`, `labels`, `fillOpacity`, and `color` from the saved source object inside the shape loop. A frame can draw up to 8 feeds of 10000 shapes, each three times for the world wraps. `AGENTS.md` forbids preference reads during frame painting.

Keep typed style fields in `Feed`. Fill them in `reconcile` and use them in `paint` and `itemsAt`.

### WMTS and WMS datasets write to the GDAL default cache

Locations: `src/plugins/gdal_raster.cpp:163-168`, `:293-303`; `src/core/gdal_support.cpp:40-60`.

Dataset sources pass `WMTS:` and `WMS:` names to GDAL without a cache setting. The GDAL WMTS driver caches tiles in `~/.cache/gdalwmscache` by default. A probe confirmed WMTS. These tiles are outside the SWAK cache limit and the disk use display. Checked and unchecked TLS sources share them. `docs/map-providers.md` says that the GDAL cache is under `maps/gdal`.

Set `GDAL_DEFAULT_WMS_CACHE_PATH` for each open to the SWAK folder for the TLS policy. Disable the cache for authenticated sources.

### Authenticated remote GDAL datasets pass validation but never load

Locations: `src/core/tiles.cpp:700-706`, `src/core/map_auth.cpp:87-92`, `src/plugins/gdal_raster.cpp:813-835`.

`validateDataset` accepts credentials for `/vsicurl/https://` and `WMTS:https://` names. `TileRenderer::setSource` checks the endpoint with `QUrl` and `authorizeMapRequest`. These names have no `https` scheme, so the check always fails. Do not only remove the check: a probe showed that GDAL sends a `GDAL_HTTP_HEADERS` bearer token to every tile host that a WMTS capabilities document names.

Reject credentials for remote dataset types in `validateDataset`, and document the limit.

### Tile failures flood the internal events

Locations: `src/core/tiles.cpp:833-848`, `:1002-1007`, `:1090`, `:1210-1213`; `src/core/maps.cpp:515-523`.

`fail` logs a warning for every failed tile. Without a network, up to about 320 tiles fail within seconds and log, and this repeats at each retry step. GDAL failures log a second time. `MapSources::restorePreferences` also logs one warning for each invalid provider, and `put` calls it, so each layer change repeats the warnings. This is the same failure type as the receiver defect in the October 2 review.

Log only when the failure state changes, with a count in the status. Log an invalid provider once until its state changes.

### Tab bars inside floating panes block the map

Locations: `src/app/map_panels.cpp:83`, `:181`.

`paintEvent` and `updateMask` search all tab bars recursively. They also find tab bars inside pane content, such as the Files pane `QTabWidget`. The tab bar loop does not skip floating panes. For a floating pane, the screen position goes into the mask. A probe showed a mask and occlusion rectangle over the open map. In Standard, that rectangle shows the window color and takes mouse input from the map. In Modern, docked panes with inner tab bars get an extra glass rectangle.

Use `Qt::FindDirectChildrenOnly` in both loops, as the event filter installation already does.

### A pane drag can keep the keyboard grab, and a drop shows a hidden pane

Locations: `src/app/map_panels.cpp:191-198`, `:278-321`, `:382-408`.

Only Escape and a mouse release or move on the drag source end a drag. Nothing ends it on focus loss, window deactivation, a modal dialog, or when the pane is hidden or deleted. A probe deleted the dragged pane during a drag. The keyboard grab and the drop indicator stayed until Escape, and keys for other widgets went to the panels. A second probe hid the pane during the drag, as Information does when its selection clears. The release still reached the pane, and `finishDrag` called `pane->show()`.

Add one `cancelDrag` and call it on deactivation, focus loss, hide, a new press during a drag, and when the pane is hidden or destroyed. Apply a drop only to a visible pane, and do not call `show`.

## Checked and correct

The reviewers confirmed these areas against the code:

- TLS: TLS 1.2 or later, peer and host name checks, and no plain fallback for TCP and QUIC. libcurl allows HTTPS only, follows no redirects, and limits size and time.
- Stream and protocol limits: TAK protocol varints, frame sizes, LAN announcements, peer counts, mailbox and backlog limits, and retry backoff.
- CoT decoding: size, depth, element, attribute, DTD, and entity limits, finite coordinates, and escaped output.
- Data packages: entry and expansion limits, path checks, owner-only folders, and `QSaveFile` writes. File shares check the hash before import.
- Tile rendering: generations, cancellation, bounded failures and queues, read limits, and the fixes from the October 2 reviews.
- Motion and prediction: animation settings stay in typed fields, and histories, traces, and predictions are bounded.
- Profiles: bounded preference input, atomic owner-only writes, and a single-instance lock.
- Logging: text logging stays off until the profile enables it. Output is rate-limited and filtered.
- Nested loops: most dialogs use `Modal` and check it after `exec`.
- Removed features: the removals in October left no code in `src/` and no references in the documents.
